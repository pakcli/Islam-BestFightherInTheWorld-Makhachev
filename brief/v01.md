# 2–3 Years Dagestan — Project Brief

## 1. What This Is

A single-page fan site that presents Islam Makhachev's meme history as a **YouTube-style playlist/channel page**, not a formal document. Each meme is a "video card" (thumbnail + title + timestamp), sorted oldest → newest, so a first-time visitor understands the whole bit in a 10-second scroll.

**Reference feel:** YouTube channel "Videos" tab / a playlist view — thumbnail grid or list rows, timestamp chips, view-count-style meta. Not a dark-mode 1:1 clone — same interaction patterns (grid/list of cards, timestamps, click-to-expand), own color and type identity.

## 2. Goals

- Fast to scan — the format should be instantly recognizable, no explanation needed
- Chronological — ordered by real date where we have one
- Honest about uncertainty — memes with no confirmed date go in a separate "Shorts / Clips" section instead of a fake timestamp
- Each card can expand (click/tap) to show the full quote, short context, and a source link if available

## 3. Page Structure

```
1. Header / Channel banner
   - Site title, one-line description, subscribe-style CTA (optional, just for flavor)

2. "Now Playing" hero
   - The #1 most iconic entry: "2-3 Years Dagestan" origin quote
   - Large card, autoplay-style framing

3. Main playlist (grid or list — see Section 5)
   - All timestamped entries, oldest → newest
   - Each = one card

4. "Shorts" row
   - Undated / recurring bits
   - Horizontally scrollable row of smaller cards, no timestamp shown

5. Footer
   - Disclaimer: fan project, not affiliated with Makhachev/UFC
   - Quotes are paraphrased from interviews/press conferences
```

## 4. Card Anatomy (per entry)

Each card needs:

| Field | Description | Example |
|---|---|---|
| `thumbnail` | Generated graphic, bold caption text on a color/gradient background — used as the poster frame before the embed loads, and as the fallback if no embed exists | Big text "GIVE ME MAYWEATHER 😭" over red/green gradient |
| `title` | YouTube-clickbait style headline | "ISLAM CALLS OUT MAYWEATHER — Joe Rogan SHOCKED" |
| `timestamp` | Real date if known, else omitted (goes to Shorts instead) | "Feb 2022" |
| `channel` | Where/who it's from — the source "channel," not a real YouTube channel necessarily | "UFC post-fight presser" / "Daniel Cormier's YouTube" / "ESPN" |
| `duration_badge` | Fun fake duration, just for visual authenticity | "0:14" |
| `meta_row` | Fake "views" / "posted X ago" style line, purely decorative | "2.1M views · UFC presser" |
| `quote` | The actual paraphrased quote | — |
| `context` | 1–2 sentence explanation | — |
| `embed_type` | `youtube` / `tiktok` / `instagram` / `x` / `none` | "youtube" |
| `embed_url` | The real video/post URL to embed | "https://youtube.com/watch?v=..." |
| `source_url` | Link out to original source (used when no embed is available, or as a "watch original" link alongside the embed) | optional |

**Click/tap behavior:** card expands in place or opens a modal. If `embed_type` is not `none`, the modal plays the actual clip (YouTube/TikTok/Instagram/X embed). If `embed_type` is `none`, the modal just shows the full quote + context + source link — same layout, embed slot simply isn't rendered.

## 4.1 Embed Requirements

Every entry *can* carry a real social/video embed — this is now a first-class part of the card, not decoration.

**Behavior:**
- Grid/list view shows the static `thumbnail` graphic only (fast page load, no iframes rendered upfront)
- On click/tap, the card expands and the real embed loads in place of (or above) the thumbnail — lazy-loaded, not rendered on initial page load
- If an entry has no real clip available yet, `embed_type: none` — show quote/context/source link only, no broken embed

**Per-platform embed patterns:**

*YouTube*
```html
<iframe
  width="100%" height="315"
  src="https://www.youtube-nocookie.com/embed/{VIDEO_ID}"
  title="{card title}"
  frameborder="0"
  allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture"
  allowfullscreen
  loading="lazy">
</iframe>
```
Use `youtube-nocookie.com` domain (privacy-friendlier embed, no functional difference for the user).

*TikTok*
Requires TikTok's official embed script (`https://www.tiktok.com/embed.js`) + a `<blockquote class="tiktok-embed">` per video — not a plain iframe. Script only needs to load once per page; re-run `window.TikTokEmbed.lib.render()` (or reload the script) after dynamically injecting new blockquotes (e.g. on modal open).

*Instagram*
Same pattern as TikTok — official embed script (`https://www.instagram.com/embed.js`) + `<blockquote class="instagram-media">`. Requires `instgrm.Embeds.process()` to be called after the blockquote is added to the DOM.

*X / Twitter*
Use `https://platform.twitter.com/widgets.js` + `<blockquote class="twitter-tweet">`, or the oEmbed API if a build-time solution is preferred over client-side script injection.

**Wrapper/responsiveness:**
- All embeds go inside a fixed-aspect-ratio container (`aspect-ratio: 16/9` for YouTube, `9/16` for TikTok/Shorts-style content) so layout doesn't jump when the embed loads
- Never let an iframe dictate the page layout directly — always constrain via a wrapper div

**Performance/safety notes:**
- Lazy-load every embed (`loading="lazy"` for iframes; only inject TikTok/Instagram/X blockquotes when the card is actually opened) — don't load 24 video embeds on initial page load
- Each platform's embed script should be loaded once and reused, not re-fetched per card
- If a clip gets taken down or a link breaks, the card should fail gracefully to the `thumbnail` + `source_url` fallback, not show a broken iframe

## 5. Layout Direction

Two acceptable approaches — pick one:

**A. Grid (channel page style)**
Responsive card grid, 3–4 columns desktop → 1 column mobile. Each card = thumbnail on top, title/meta below. Closest to a YouTube channel's "Videos" grid.

**B. List (playlist style)**
Vertical stacked rows, thumbnail left + text right, like YouTube's playlist sidebar. Easier to read as a strict timeline since it's naturally single-column.

Recommend **A for the main grid, B (horizontal scroll) for the Shorts row**.

## 6. Scroll Progress Timeline Bar

New core interaction: as the user scrolls through the main playlist, a **timeline bar tracks position and fills like a video scrubber** — reinforcing the "this is one long timeline, not a random grid" idea.

**Behavior:**
- A bar (horizontal, pinned to top of viewport under the header — or vertical, pinned to the left edge on desktop) spans the full date range of the timeline (2021–2022 → Jun–Jul 2026)
- A filled/progress segment grows as the user scrolls down through the main playlist, same visual language as a YouTube video's red scrubber
- Small tick marks or dots along the bar mark each entry's position, proportional to its real date (not evenly spaced — a 2023 cluster should sit close together, the 2024→2025 jump should show a gap)
- The current/nearest entry's date + title shows as a small floating label on the bar (like a scrubber tooltip), updating on scroll
- Clicking/tapping a tick jumps the page to that entry (scrub-to-seek)
- On mobile: bar collapses to a slim horizontal strip pinned to top, tooltip still works on scroll, tap-to-seek still works
- Only spans the **main timestamped playlist** (Section 7.1) — the Shorts row is undated and sits outside the bar's range, unaffected by it

**Tech approach:** scroll-linked, not scroll-jacked — use scroll position / IntersectionObserver to update fill %, don't hijack native scroll behavior or add scroll-snap unless specifically requested later.

Each entry object should include `embedType` and `embedUrl` fields per Section 4.1 — **none of the real clip URLs are sourced yet** (see Section 9), so ship with `embedType: "none"` as the default and swap in real values as clips are found.

## 8. Visual Direction

- Reference YouTube UI **patterns** (card grid, timestamp chips, red accent, clean sans-serif), not a literal skin
- Own color identity — not YouTube red/white/black as-is; give it Dagestan/UFC flavor (deep green, red, gold — open to programmer/designer input)
- Thumbnails are **generated graphics** (bold text over color/gradient), never real photos — avoids rights issues and keeps a consistent, ownable visual style across all cards
- Keep it fast and lightweight — this is a fun scroll, not a heavy app

## 9. Tech Notes (flexible — programmer's call)

- Content should live in a data file, not hardcoded HTML, so entries are easy to add later
- Static site is fine — no backend needed
- Should be responsive down to mobile (this will get shared as a link on socials)
- Card expand (click/tap) to show full quote + context + embed inline, rather than navigating away — see Section 4.1 for embed loading behavior
- Load platform embed scripts (YouTube needs none; TikTok/Instagram/X need their JS) once globally, not per-card
- Scroll progress bar (Section 6) should use scroll position / IntersectionObserver, not a scroll-jacking library
- Nice-to-have: subtle scroll-in animation for cards (optional, keep it light — don't overdo it)
